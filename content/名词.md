1.  LBS广告：Location Based Services Advertising，“位置定向广告”

通过手机 GPS、基站、Wi‑Fi、IP 地址、POI/商圈等位置信息，判断用户当前或历史所在区域，然后向用户投放与位置相关的广告。

举例：

● 你在某商场附近，刷到该商场餐饮店的优惠券广告；

● 你到某个城市出差，App 给你推送附近酒店、租车、餐厅广告；

● 奶茶店只想投放门店周边 333 公里内的人群，就可以用 LBS 广告；

● 房产、教育、健身、医美等行业按城市、商圈、小区、写字楼附近定向投放。

核心：

在合适的地点，把广告推给附近或到过相关地点的人。

常见形式包括：

1.  实时位置广告：用户现在在某区域，就推送附近广告。

2.  商圈/门店周边定向：围绕门店半径投放，如 111 公里、333 公里、555 公里。

3.  到访人群定向：曾经去过某商场、机场、学校、竞品门店的人。

4.  本地生活广告：餐饮、零售、美容、健身、汽车、房产等线下业务常用。

5.  地图/导航广告：在地图 App、导航路线、附近搜索中展示广告。

它的优点是精准、转化路径短、适合线下门店引流；缺点是依赖定位权限和数据准确性，也涉及用户隐私合规问题。

2.  长尾样本 = 少见但重要、数量少但风险高、变化多且难以被模型稳定识别的边缘违规广告样本。

核心价值是：

补齐模型在低频复杂违规场景上的识别能力，降低风险漏放。

3.  AUC 和 ROC

ROC 曲线反映的是模型在不同风险阈值下，风险广告召回率和正常广告误伤率之间的权衡关系。

AUC 是 ROC 曲线下面积，用来衡量模型整体排序能力。AUC 越高，说明模型越能把真实风险广告排在正常广告前面，从而在相同人审资源下提升风险识别效率，或者在相同风险控制目标下降低正常广告误伤。
# 一、大模型训练相关

## 1. torchrun

**torchrun 是 PyTorch 官方提供的分布式训练启动工具。**

它的作用是：  
**把同一个训练任务启动到多张 GPU 上一起跑。**

常见命令：

```
torchrun --nproc_per_node=4 train.py
```

意思是：当前机器使用 4 张 GPU / 4 个进程训练。

你可以理解为：

> **torchrun = 多卡训练启动器**

适合普通深度学习模型、多 GPU 训练，例如分类、检测、分割、图像融合、大模型微调等。

---

## 2. DDP

**DDP 全称 Distributed Data Parallel，分布式数据并行。**

它是 PyTorch 多卡训练中很常见的一种方式。

简单理解：

```
GPU0 处理一部分数据GPU1 处理一部分数据GPU2 处理一部分数据GPU3 处理一部分数据
```

每张 GPU 都有一份完整模型，但处理不同 batch 的数据，然后同步梯度。

一句话：

> **DDP = 多张卡各自算一部分数据，最后同步参数。**

---

## 3. DeepSpeed

**DeepSpeed 是微软开源的大模型训练加速和显存优化框架。**

它主要解决：

```
模型太大显存不够多卡训练效率低优化器状态占显存太多
```

你可以理解为：

> **DeepSpeed = 大模型训练优化器**

它比 torchrun 更偏向大模型训练，特别适合 LLM / 多模态模型。

---

## 4. ZeRO

**ZeRO 是 DeepSpeed 里的核心显存优化技术。**

普通训练时，每张 GPU 都要保存完整的：

```
模型参数梯度优化器状态
```

ZeRO 会把这些东西拆开，分摊到不同 GPU 上。

可以理解为：

> **ZeRO = 把模型训练时占显存的东西切开，分给多张卡保存。**

常见有：

|类型|含义|
|---|---|
|ZeRO-1|切分优化器状态|
|ZeRO-2|切分优化器状态 + 梯度|
|ZeRO-3|切分优化器状态 + 梯度 + 模型参数|

ZeRO-3 最省显存，但通信和配置也更复杂。

---

## 5. Offload

**Offload 指把部分训练数据从 GPU 显存转移到 CPU 内存，甚至硬盘上。**

比如：

```
参数放 GPU优化器状态放 CPU部分状态放 NVMe 硬盘
```

好处是省显存。  
坏处是速度可能变慢。

一句话：

> **Offload = 用速度换显存。**

---

# 二、大模型微调工具相关

## 6. LLaMA-Factory

**LLaMA-Factory 是一个大模型微调工具箱。**

虽然名字叫 LLaMA-Factory，但它不只支持 LLaMA，也支持很多模型，例如：

```
QwenLLaMADeepSeekGLMGemmaMistralPhi多模态模型
```

它主要用来做：

```
SFT 微调LoRA 微调QLoRA 微调DPO 对齐模型导出模型推理WebUI 可视化训练
```

一句话：

> **LLaMA-Factory = 帮你更方便微调大模型的工具。**

---

## 7. SFT

**SFT 全称 Supervised Fine-Tuning，监督微调。**

它是最常见的大模型微调方式。

数据格式通常类似：

```
{  "instruction": "判断这条广告是否违规",  "input": "7天根治糖尿病，无效退款",  "output": "违规，原因是涉及医疗功效承诺和虚假宣传"}
```

模型学习的是：

```
给定问题 → 输出标准答案
```

一句话：

> **SFT = 用人工标注好的问答数据教模型怎么回答。**

广告审核场景可以用来做：

```
风险识别违规原因生成审核建议生成规则解释样本自动标注
```

---

## 8. LoRA

**LoRA 是一种轻量级微调方法。**

全参数微调是把整个大模型都训练一遍，显存消耗很大。

LoRA 的思路是：

```
原模型大部分参数不动只训练一小部分新增参数
```

优点：

```
显存占用低训练速度快保存文件小适合个人或小团队微调
```

一句话：

> **LoRA = 不动大模型主体，只训练外挂小参数。**

---

## 9. QLoRA

**QLoRA 是更省显存的 LoRA。**

它会先把大模型量化到 4bit / 8bit，再进行 LoRA 微调。

可以理解为：

```
LoRA = 轻量微调QLoRA = 量化后的轻量微调，更省显存
```

一句话：

> **QLoRA = 显存更省的大模型微调方式。**

如果你的显卡显存不大，比如 16GB，QLoRA 会比全参数微调现实很多。

---

## 10. DPO

**DPO 全称 Direct Preference Optimization，直接偏好优化。**

它不是简单地教模型标准答案，而是告诉模型：

```
这个回答更好那个回答更差
```

例如广告审核场景：

```
问题：这条广告为什么违规？好回答：指出医疗功效承诺、虚假宣传，并给出拦截建议。差回答：只说“违规”，没有解释原因。
```

DPO 用来让模型更符合人的偏好。

一句话：

> **DPO = 让模型学会更偏向人类认为更好的回答。**

---

# 三、分类任务相关

## 11. Binary Classification

**Binary Classification 是二分类。**

意思是一个样本只判断两个结果之一。

广告审核例子：

```
违规 / 不违规通过 / 拦截风险 / 正常
```

一句话：

> **二分类 = 二选一。**

---

## 12. Multi-class Prediction

**Multi-class Prediction 是多分类预测。**

意思是一个样本只能属于多个类别中的一个。

例如广告行业分类：

```
食品美妆教育金融医疗游戏
```

一条广告最终只能归到其中一个主类别。

一句话：

> **多分类 = 多个类别里只能选一个。**

---

## 13. Multi-label Prediction

**Multi-label Prediction 是多标签预测。**

意思是一个样本可以同时属于多个类别。

广告审核例子：

```
一条广告可能同时命中：虚假宣传医疗功效诱导点击资质不明
```

它不是只能选一个，而是可以多个标签同时成立。

一句话：

> **多标签预测 = 一个样本可以打多个标签。**

这是广告审核里非常常见的任务，因为一条广告经常同时存在多个风险点。

---

## 14. Label

**Label 是标签。**

在机器学习里，标签就是样本的标准答案。

例如：

```
广告文本：3天瘦20斤，无效退款标签：虚假宣传、夸大承诺
```

标签可以是：

```
二分类标签：违规 / 不违规多分类标签：医疗 / 金融 / 教育多标签标签：虚假宣传 + 医疗功效 + 诱导点击
```

---

# 四、PR 曲线与评估指标

## 15. Precision

**Precision 是精确率。**

它表示：

> 模型判为风险的样本里，真正有风险的比例。

公式：

```
Precision = TP / (TP + FP)
```

广告审核里可以理解为：

> **模型拦截的广告里，有多少是真的违规。**

Precision 越高，说明误伤越少。

---

## 16. Recall

**Recall 是召回率。**

它表示：

> 所有真实风险样本里，被模型找出来的比例。

公式：

```
Recall = TP / (TP + FN)
```

广告审核里可以理解为：

> **所有违规广告里，有多少被模型抓住了。**

Recall 越高，说明漏放越少。

---

## 17. PR 曲线

**PR 曲线全称 Precision-Recall Curve，精确率-召回率曲线。**

横轴通常是：

```
Recall
```

纵轴通常是：

```
Precision
```

它表示在不同阈值下，模型的精确率和召回率变化情况。

一句话：

> **PR 曲线 = 看模型在“少误伤”和“少漏放”之间怎么权衡。**

在广告审核、风控、欺诈检测这类正负样本极不均衡的场景中，PR 曲线很有价值。

---

## 18. Threshold

**Threshold 是阈值。**

模型通常会输出一个风险分数：

```
广告A：0.92广告B：0.61广告C：0.32
```

如果阈值设为 0.5：

```
分数 >= 0.5 → 判为风险分数 < 0.5 → 判为正常
```

阈值越高：

```
拦截更谨慎Precision 可能提高Recall 可能下降误伤少，但漏放可能增加
```

阈值越低：

```
拦截更激进Recall 可能提高Precision 可能下降漏放少，但误伤可能增加
```

---

## 19. TP / FP / FN / TN

这是分类模型评估里最基础的四个概念。

| 名词  | 含义  | 广告审核例子    |
| --- | --- | --------- |
| TP  | 真阳性 | 违规广告被正确拦截 |
| FP  | 假阳性 | 正常广告被误拦   |
| FN  | 假阴性 | 违规广告被漏放   |
| TN  | 真阴性 | 正常广告被正确放行 |

在广告审核里：

```
FP = 误伤FN = 漏放
```

这两个特别重要。

---

## 20. AP / AUPRC

**AUPRC 是 PR 曲线下面的面积。**

**AP 是 Average Precision，平均精确率。**

很多时候可以把它们理解成类似概念：

> **衡量 PR 曲线整体表现的综合指标。**

一般来说：

```
AP / AUPRC 越高，模型整体越好
```

但业务上不能只看 AP，还要看具体策略点，比如：

```
在 Recall = 90% 时，Precision 是多少？在 Precision = 95% 时，Recall 是多少？
```

---
## 21. Groundtruth
**Ground truth** 一般翻译为：**真实标签 / 标准答案 / 真值 / 人工标注结果**。

在机器学习、图像处理、检测、分割等任务里，它表示模型要学习或对比的“正确答案”。

# 五、ROC / AUC 相关

## 21. ROC 曲线

**ROC 曲线全称 Receiver Operating Characteristic Curve。**

它看的是：

```
TPR 和 FPR 的关系
```

其中：

```
TPR = 真正率 = RecallFPR = 假正率
```

广告审核里：

```
TPR：违规广告被抓住的比例FPR：正常广告被误伤的比例
```

ROC 越靠左上角，模型区分能力越强。

---

## 22. AUC

**AUC 是 ROC 曲线下面的面积。**

AUC 越大，模型整体区分正负样本的能力越强。

可以粗略理解为：

> **模型把违规广告排在正常广告前面的能力。**

AUC = 1，代表非常完美。  
AUC = 0.5，接近随机猜测。

---

## 23. ROC 和 PR 的区别

|对比项|ROC 曲线|PR 曲线|
|---|---|---|
|横轴|FPR|Recall|
|纵轴|TPR / Recall|Precision|
|重点|整体区分能力|正样本识别质量|
|适合场景|样本较均衡|正负样本不均衡|
|广告审核|可参考|通常更重要|

广告审核中，违规样本通常远少于正常样本，所以 **PR 曲线往往比 ROC 曲线更敏感**。

---

# 六、样本难度相关

## 24. Positive Sample

**Positive Sample 是正样本。**

在广告审核里，通常指：

```
违规广告风险广告应该拦截的广告
```

例如：

```
3天根治糖尿病，无效退款
```

这就是风险正样本。

---

## 25. Negative Sample

**Negative Sample 是负样本。**

在广告审核里，通常指：

```
正常广告合规广告可以放行的广告
```

例如：

```
新鲜苹果产地直发，今日特价
```

这就是普通负样本。

---

## 26. Easy Negative

**Easy Negative 是简单负样本。**

它真实是负样本，而且模型很容易判断它是负样本。

广告审核例子：

```
今日新鲜苹果，产地直发
```

如果任务是识别违规医疗广告，这种样本明显不是医疗违规广告，模型很容易判断。

一句话：

> **Easy negative = 很容易识别的正常样本。**

---

## 27. Hard Negative

**Hard Negative 是困难负样本。**

它真实是负样本，但长得很像正样本，模型容易误判。

广告审核例子：

```
糖尿病患者饮食管理科普：如何控制每日糖分摄入
```

这条内容提到了“糖尿病”，但它可能只是科普，不是违规广告。

模型如果只看关键词，可能会误判成医疗违规。

一句话：

> **Hard negative = 真实没问题，但看起来很像有问题的样本。**

Hard negative 主要用来降低误伤。

---

## 28. Hard Positive

**Hard Positive 是困难正样本。**

它真实是正样本，但模型容易误判成负样本。

广告审核例子：

```
三天恢复年轻状态，秘密配方，限时抢购
```

它可能没有直接写“治疗”“根治”，但有明显夸大承诺和诱导转化风险。

模型如果只依赖关键词，可能会漏掉。

一句话：

> **Hard positive = 真实有问题，但看起来不明显的风险样本。**

Hard positive 主要用来降低漏放。

---

## 29. Hard Negative Mining

**Hard Negative Mining 是困难负样本挖掘。**

意思是：  
专门找那些模型容易误判的负样本，加入训练集。

广告审核里常见做法：

```
找被模型误拦的正常广告人工确认它们确实合规加入 hard negative 数据集重新训练模型
```

这样模型会学会：

```
不是出现“糖尿病”就违规不是出现“贷款”就高风险不是出现“减肥”就虚假宣传要结合上下文、承诺方式、资质、落地页内容判断
```

一句话：

> **Hard negative mining = 专门收集容易误伤的正常样本来训练模型。**

---

你可以重点记这一组：

| 机器学习名词        | 广告审核里的意思         |
| ------------- | ---------------- |

| Multi-label   | 一条广告可以同时命中多个风险标签 |

# 八、最简复习版

最后给你一个极简记忆版：

```
torchrun：PyTorch 多卡训练启动器。DeepSpeed：大模型训练加速和省显存框架。LLaMA-Factory：大模型微调工具箱。SFT：用标注好的问答数据教模型回答。LoRA：只训练少量新增参数，省显存。QLoRA：量化后的 LoRA，更省显存。Multi-label prediction：一个样本可以同时打多个标签。Precision：模型拦截的样本里，有多少是真的违规。关注误伤。Recall：真实违规样本里，有多少被模型抓住。关注漏放。PR 曲线：看 Precision 和 Recall 的权衡。ROC 曲线：看 TPR 和 FPR 的权衡。AUC：模型区分正负样本的整体能力。Hard negative：真实正常，但很像违规，容易被误伤。Hard positive：真实违规，但不明显，容易被漏放。
```

你复习时可以抓住一句核心：

> **广告审核模型的本质，就是在 Precision 和 Recall 之间找平衡：既要少误伤正常广告，也要少漏放风险广告。**


**空标签打标** 和 **空跑** 都是业务/数据/模型场景里的常见口语说法。公开资料里“标签体系”通常就是给数据或对象加标签，用来分类和描述对象特征；你问的这两个词更像公司内部流程话术。

## 1. 空标签打标是什么意思？

**空标签打标 = 样本看了，但没有命中任何可选标签，所以标成“空/无/不适用”。**

它不是“不打标”，而是明确告诉系统：

> 这个样本我审核过了，但它不属于当前标签体系里的任何一个标签。

比如广告审核里有一批风险标签：

```
夸大宣传低俗擦边虚假资质诱导点击医疗违规
```

现在来了一个广告样本，人工审核后发现它没有这些问题，那么可以打成：

```
空标签 / 无风险 / 无命中 / none / negative
```

### 举例

一个广告文案是：

```
夏季新品 T 恤，第二件半价。
```

审核员看完后发现：

```
不虚假不低俗不诱导不违规
```

那它就可能被打成 **空标签**。

### 它和漏标不一样

**空标签**：我看过了，确认没有命中标签。  
**漏标**：它本来应该命中某个标签，但审核员没标出来。

比如：

```
广告：三天治好糖尿病，100%有效。
```

应该标：医疗夸大 / 虚假宣传。  
如果审核员标成空标签，这就不是正常空标签，而是**漏标/错标**。

---

## 2. 空跑是什么意思？

**空跑 = 让系统、规则、模型或流程先跑起来，但暂时不真正影响线上结果。**

你可以理解成：

> 先试运行，只观察效果，不真的拦截、不真的处罚、不真的改变用户看到的结果。

英文里有点像：

```
dry runshadow run灰度旁路验证
```

### 广告审核里的例子

假设你们新做了一条审核规则：

```
命中“100%根治”“包治百病”的广告，判为医疗夸大。
```

但是你不敢一上线就直接拦截，因为可能误伤正常广告。

所以先让它**空跑一周**：

```
规则照常扫描广告命中了就记录日志但不真的拦截广告也不影响审核结果
```

然后看数据：

```
命中了多少广告？其中多少是真的违规？误伤率高不高？漏放有没有减少？
```

如果效果好，再正式上线生效。

---

## 3. 两个词放在一起理解

可以这样记：

```
空标签打标：打标结果为空，表示样本没有命中任何标签。空跑：流程/规则/模型先跑，但不真正生效。
```

更口语一点：

```
空标签打标 = 这个样本看过了，没问题，标“无”。空跑 = 先偷偷跑一遍看看效果，别急着上线影响业务。
```

在广告审核业务里，**空跑**通常用于新规则、新模型、新策略上线前验证；**空标签打标**通常用于样本标注、模型训练、质检回流里面区分“正常样本”和“风险样本”。
